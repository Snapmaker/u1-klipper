# Vulnerability Advisory: SEC-02

## Metadata & Reporting Context
- **Report Date:** November 3, 2026
- **Target Software:** Snapmaker OrcaSlicer (v2.4.1)
- **Vulnerability Identifier:** SEC-02
- **Vulnerability Title:** Global TLS Certificate Verification Disabled by Default in HTTP Client
- **Affected Components:** `src/slic3r/Utils/Http.cpp`
- **Vulnerability Classification:** CWE-295 (Improper Certificate Validation)
- **CVSS v3.1 Score:** 9.1 (CRITICAL) - `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N`
- **Security Contact:** Snapmaker OrcaSlicer Security Team (`softfeverever@gmail.com`)

---

## Scope of Vulnerability
- **Affected Users & Systems:** All OrcaSlicer installations performing network communications via the native `Http` utility class (including preset syncing, model downloads from cloud repositories, update checking, and cloud authentication).
- **Threat Actor Profile:** Network-adjacent or upstream attacker (Man-in-the-Middle / MitM, rogue Wi-Fi access point, compromised DNS, or malicious gateway).

---

## Executive Summary
A critical vulnerability exists in `Http.cpp` where libcurl's SSL certificate validation options (`CURLOPT_SSL_VERIFYPEER` and `CURLOPT_SSL_VERIFYHOST`) are hardcoded to `0L` upon initialization of every HTTP client session. Consequently, all TLS connections silently accept invalid, expired, self-signed, or forged certificates. This renders encrypted communications completely vulnerable to transparent interception, modification, and credential theft.

---

## Technical Root Cause Analysis
In `Http::priv::priv(const std::string &url)`, the libcurl session handle is configured as follows:

```cpp
// E:/KI Projekte/OrcaSlicer/src/slic3r/Utils/Http.cpp:205-206
::curl_easy_setopt(curl, CURLOPT_SSL_VERIFYPEER, 0L);
::curl_easy_setopt(curl, CURLOPT_SSL_VERIFYHOST, 0L);
```

1. **`CURLOPT_SSL_VERIFYPEER = 0L`**: Instructs libcurl not to verify the peer's certificate authenticity against trusted Certificate Authorities (CAs).
2. **`CURLOPT_SSL_VERIFYHOST = 0L`**: Instructs libcurl not to verify whether the Common Name (CN) or Subject Alternative Name (SAN) in the server's certificate matches the requested hostname.

Because this configuration is set in the base constructor of `Http::priv`, every outbound HTTPS request generated by this component inherits the disabled verification policy.

---

## Steps to Reproduce
1. Configure an intercepting proxy (e.g., mitmproxy or Charles Proxy) with a self-signed root CA certificate not trusted by the host OS.
2. Route OrcaSlicer network traffic through the proxy.
3. Trigger an action utilizing `Http.cpp` (such as checking for updates, downloading model assets, or cloud sync).
4. Observe that the HTTPS request completes successfully with a 200 OK status without throwing any certificate validation error or warning to the user.

---

## Attack Scenario & Threat Analysis
1. An attacker on an untrusted network (such as a shared workshop Wi-Fi network) performs ARP spoofing or DNS spoofing.
2. When OrcaSlicer issues an HTTPS request to fetch slicing profiles, firmware updates, or cloud data, the attacker responds with a fraudulent server certificate.
3. Because certificate verification is disabled, OrcaSlicer establishes a secure TLS tunnel directly with the attacker.
4. The attacker intercepts authentication bearer tokens, API keys, or injects manipulated slicing parameters and malicious G-code into the user's workflow.

---

## Defensive Remediation & Verification

### Code Fix
Enable strict peer and hostname verification by default, utilizing the operating system certificate store:

```cpp
// E:/KI Projekte/OrcaSlicer/src/slic3r/Utils/Http.cpp:205
::curl_easy_setopt(curl, CURLOPT_SSL_VERIFYPEER, 1L);
::curl_easy_setopt(curl, CURLOPT_SSL_VERIFYHOST, 2L);

#ifdef _WIN32
// Leverage Windows Crypt32 Certificate Store
::curl_easy_setopt(curl, CURLOPT_SSL_OPTIONS, CURLSSLOPT_NATIVE_CA);
#endif
```

For users connecting to local self-hosted printer endpoints using self-signed certificates, provide an explicit, user-configurable setting per device (such as "Ignore TLS Certificate Warnings for Local Printer") rather than disabling security globally across the entire software suite.

### Security Recommendations
- Always verify digital certificates against a trusted root certificate authority bundle.
- Never set `CURLOPT_SSL_VERIFYPEER` or `CURLOPT_SSL_VERIFYHOST` to 0 in production code.
